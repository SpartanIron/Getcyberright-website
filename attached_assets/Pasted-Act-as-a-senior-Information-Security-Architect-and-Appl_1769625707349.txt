Act as a senior Information Security Architect and Application Security Engineer with deep expertise in enterprise security standards including ISO/IEC 27001, NIST Cybersecurity Framework, NIST SP 800-53, OWASP ASVS, OWASP Top 10, CIS Critical Security Controls, SOC 2 Trust Services Criteria, and GDPR principles.

You are tasked with implementing enterprise-grade security by design for this website and its supporting infrastructure using open-source tools only.

Objectives

Design, document, and implement a comprehensive security architecture that protects against modern threats including phishing, account takeover, injection attacks, data breaches, supply-chain compromise, insider threats, and denial-of-service attacks.

Scope

The solution must cover:
	1.	Application Security
	•	Secure authentication and authorization (RBAC, MFA-ready)
	•	Secure session management
	•	Input validation and output encoding
	•	Protection against OWASP Top 10 vulnerabilities
	•	Secure API design and rate limiting
	2.	Infrastructure & Hosting Security
	•	Hardened Linux server configuration
	•	Network segmentation and firewall rules
	•	TLS configuration and certificate management
	•	Secrets management (no plaintext secrets in code)
	•	Backup, recovery, and high availability considerations
	3.	Open-Source Security Tooling
Select and justify open-source tools for:
	•	Web Application Firewall (WAF)
	•	Static Application Security Testing (SAST)
	•	Dependency and supply-chain scanning
	•	Dynamic Application Security Testing (DAST)
	•	Container and image scanning (if applicable)
	•	Intrusion detection and monitoring
	•	Log aggregation and SIEM-like alerting
	4.	Identity, Access & Data Protection
	•	Password hashing and storage best practices
	•	Role-based access control model
	•	Encryption at rest and in transit
	•	Secure handling of PII and sensitive data
	•	Privacy-by-design principles
	5.	Compliance & Governance
	•	Map implemented controls to:
	•	ISO 27001 Annex A
	•	NIST CSF core functions
	•	CIS Critical Security Controls
	•	OWASP ASVS levels
	•	Provide a lightweight security policy framework
	•	Include secure SDLC and change-management guidance
	6.	Threat Modeling & Risk Management
	•	Perform a threat model (STRIDE or equivalent)
	•	Identify high-risk attack paths
	•	Recommend mitigations and compensating controls
	7.	Incident Response & Monitoring
	•	Logging strategy
	•	Alerting thresholds
	•	Incident response playbooks
	•	Breach containment and recovery steps

Deliverables
	•	A clear security architecture diagram (described in text)
	•	A tooling stack with justification
	•	Configuration examples where appropriate
	•	A security implementation checklist
	•	A phased rollout plan (MVP → enterprise-ready)

Constraints
	•	Use only open-source tools
	•	Avoid vendor lock-in
	•	Prioritize usability for non-technical administrators
	•	Assume limited budget but high security expectations

Provide the response in a structured, implementation-ready format with practical, actionable guidance.
