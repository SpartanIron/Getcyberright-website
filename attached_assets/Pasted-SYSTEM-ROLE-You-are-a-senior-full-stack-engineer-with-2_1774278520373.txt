EXPOSURE REPORT TYPE DEFINITION

Define this type before writing any pipeline code.
All pipeline functions must conform to it exactly.

type BrokerResult = {
  broker: string;
  status: 'found' | 'not_found' | 'pending_verification'
        | 'rate_limited' | 'timed_out' | 'unavailable';
  url: string;
  found: boolean | null;
  dataFound: string[] | null;
  // e.g. ['phone', 'address', 'relatives']
}

type BreachResult = {
  source: 'haveibeenpwned' | 'dehashed';
  breachName: string;
  breachDate: string | null;
  dataClasses: string[];
  // e.g. ['email', 'password', 'phone']
}

type ExposureReport = {
  scanId: string;
  completedAt: string;
  brokerResults: BrokerResult[];
  breachResults: BreachResult[];
  exposureScore: 'low' | 'medium' | 'high' | 'critical';
  scoreBreakdown: {
    breachPoints: number;
    brokerPoints: number;
    sensitivityMultiplier: number;
    rawTotal: number;
  };
  partialResults: boolean;
  // true if any check returned rate_limited,
  // timed_out, or unavailable
}

EXPOSURE SCORING ALGORITHM

Score is calculated from three weighted dimensions:

Breach Count (HaveIBeenPwned + dehashed):
  0 breaches        = 0 points
  1-2 breaches      = 10 points
  3-5 breaches      = 25 points
  6+ breaches       = 40 points

Broker Presence (confirmed hits across 7 broker scaffold):
  0 brokers         = 0 points
  1-2 brokers       = 10 points
  3-4 brokers       = 20 points
  5+ brokers        = 30 points

Data Sensitivity Multiplier:
  Financial data exposed         = 1.5x total
  SSN or government ID exposed   = 2x total
  Contact info only              = 1x total

Final thresholds:
  0-20    = Low
  21-45   = Medium
  46-70   = High
  71+     = Critical

Store raw dimension scores in raw_results JSONB alongside 
final score so scoring logic can be audited and adjusted 
without re-scanning.

ERROR HANDLING CONTRACT

Every scan job must handle these failure modes explicitly:

API rate limit (429):
  Retry with exponential backoff, maximum 3 attempts, 
  intervals of 2s / 4s / 8s. If all retries fail, mark 
  that specific check as 'rate_limited' in raw_results 
  and continue the scan. Do not fail the entire job for 
  one API's rate limit.

API timeout (over 10 seconds):
  Mark check as 'timed_out' and continue.

Database write failure:
  Retry once after 1 second. If second attempt fails, 
  return 503 to client with message:
  "We could not save your scan results. 
  Please try again in a few minutes."

BullMQ job timeout:
  Set job timeout to 90 seconds. On timeout, update scan 
  status to 'failed' and surface:
  "Your scan took too long to complete. This sometimes 
  happens during high traffic. Please try again."

Network failure mid-scan:
  Partial results are better than no results. Complete all 
  checks that succeed. Mark failed checks as 'unavailable'. 
  Return completed scan with partial results banner.

Never show a raw error message, stack trace, or HTTP status 
code to the end user under any circumstance.

DATABASE SCHEMA (PostgreSQL on Railway)

CREATE TABLE scans (
  scan_id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  first_name        TEXT NOT NULL,
  last_name         TEXT NOT NULL,
  email             TEXT NOT NULL,
  phone             TEXT,
  zip               TEXT,
  exposure_score    TEXT CHECK (
                      exposure_score IN (
                        'low','medium','high','critical'
                      )
                    ),
  raw_results       JSONB,
  status            TEXT NOT NULL DEFAULT 'pending' CHECK (
                      status IN (
                        'pending','processing','complete','failed'
                      )
                    ),
  consent_given     BOOLEAN NOT NULL DEFAULT FALSE,
  consent_timestamp TIMESTAMPTZ,
  consent_ip        TEXT,
  deleted_at        TIMESTAMPTZ
);

CREATE TABLE leads (
  lead_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  scan_id          UUID REFERENCES scans(scan_id),
  last_scan_id     UUID REFERENCES scans(scan_id),
  email            TEXT NOT NULL,
  alert_email      TEXT NOT NULL,
  next_scan_due    TIMESTAMPTZ DEFAULT NOW() + INTERVAL '30 days',
  created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  opted_in         BOOLEAN DEFAULT TRUE
);

CREATE INDEX idx_scans_email ON scans(email);
CREATE INDEX idx_scans_status ON scans(status);
CREATE INDEX idx_leads_next_scan ON leads(next_scan_due);
