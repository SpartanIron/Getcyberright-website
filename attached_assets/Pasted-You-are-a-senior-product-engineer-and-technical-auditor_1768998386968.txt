You are a senior product engineer and technical auditor with experience building consumer cybersecurity tools.

Your task is to perform a brutally honest, non-emotional evaluation of GetCyberRight.com as it exists today, identify what is objectively weak, missing, or underperforming, and produce a practical enhancement plan that can be implemented inside a Replit project.

Do not be polite. Do not preserve features that do not contribute to repeat usage. If something is unnecessary, say so clearly.

⸻

REQUIRED OUTPUTS (ALL MUST BE INCLUDED)

1. Current-State Technical & Product Audit

Analyze the existing GetCyberRight.com experience and document:
	•	What features exist now.
	•	What is surface-level or cosmetic rather than functional.
	•	Where real utility breaks down for a non-technical family user.
	•	Where users will leave because nothing actionable happens.

Call out weaknesses directly.

⸻

2. Comparative Pattern Analysis

Compare the site’s current functionality against effective scam-check and consumer safety tools.

Focus on:
	•	Speed to value.
	•	Verdict clarity.
	•	Evidence transparency.
	•	User trust signals.
	•	Retention mechanics.

Extract only patterns that increase repeat usage. Ignore branding and marketing comparisons.

⸻

3. Gap Analysis (No Soft Language)

Create a table that clearly shows:
	•	What exists.
	•	What partially exists but fails.
	•	What is missing entirely.

Rank gaps by:
	1.	Impact on usefulness.
	2.	Impact on retention.
	3.	Implementation feasibility in Replit.

⸻

4. Enhancement Plan (Build, Do Not Rebuild)

A. Scam Checker (Primary Feature)
Design or enhance a Scam Checker that:
	•	Accepts URLs, phone numbers, emails, crypto wallets, and screenshots.
	•	Returns a single verdict: Safe, Suspicious, or Dangerous.
	•	Explains the verdict in plain English.
	•	Shows supporting signals from multiple data sources.
	•	Provides one explicit next action.

Specify:
	•	What code modules are needed.
	•	What external APIs should be integrated.
	•	What logic is deterministic vs AI-assisted.
	•	What should be removed if it adds no value.

⸻

B. Retention Layer (If This Is Missing, Say So)
Define the minimum viable retention system, including:
	•	Scan history.
	•	Watchlists.
	•	Change alerts.
	•	Shareable result pages.

Explain:
	•	Whether authentication is necessary.
	•	How to implement this simply in Replit.
	•	How to avoid storing unnecessary personal data.

⸻

C. Guidance Layer (Human Readability Test)
Design a guidance system that:
	•	Assumes zero cybersecurity knowledge.
	•	Explains results at an 8th-grade reading level.
	•	Tells users exactly what to do next.

If existing content fails this test, state it explicitly.

⸻

5. Homepage & Navigation Corrections

Rewrite homepage priorities to:
	•	Remove passive education as the primary value.
	•	Push immediate utility first.
	•	Reduce decision fatigue.
	•	Make the Scam Checker unavoidable.

Provide revised copy and navigation logic that can be implemented without a redesign.
